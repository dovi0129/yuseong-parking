# 점검 경로·민원 처리 API

화면과 독립적인 공개 함수는 `api.py`에 있다. 호출 예시는 `reports/2026-10-31_Worker_1_api_handoff.md`에 있다. Worker_3의 화면은 `ui/`에 있고, 기존 `app/`은 보관용이며 8501 시험 서버를 종료하였다. 화면은 `ui/`만 사용한다.

## 실행

```bash
.venv/bin/python -m unittest src.optimizer.test_contract src.optimizer.test_api -v
.venv/bin/python -m src.optimizer.run_v1 --only all
.venv/bin/python -m src.optimizer.run_v1 --only figures
.venv/bin/python -m src.optimizer.processing --date 2024-10-02 --start 17:00 --end 21:00 --vehicles 2
.venv/bin/streamlit run ui/main.py --server.address 127.0.0.1 --theme.primaryColor '#1f5f9c' --theme.base light
```

런처는 `artifacts/logs/optimizer_*_launcher_v1.log`와 `data/processed/routes/run_status.json`을 남기며, 성공 시 `evaluation.done`을 만든다. 이미 완료된 평가를 다시 할 필요 없이 `--only figures` 또는 `--only exports`를 선택할 수 있다. CSV는 `artifacts/exports/`에 utf-8-sig로 저장하고 행 수·열 이름을 재확인한다. 기존 패키지 버전은 바꾸지 않았고 화면 캡처용 추가 패키지는 `requirements_Worker_1.txt`에 기록하였다.

## 입력·시간·후보 계약

- 입력은 Worker_2의 `spots.csv`, `priority_train.csv`, `priority_choice.json`, `reports.parquet`이다. 날짜는 2024년을 지원한다. 다른 연도는 공휴일 목록을 보강해야 한다.
- 계획은 1~9월 학습 자료만 사용하고, 점수 방식은 1~7월 적합·8~9월 검증으로 고른 `shrinkage`를 기본값으로 읽는다. 공식 평가에서는 10~12월 결과로 방식을 바꾸지 않는다.
- 최종 후보는 **학습 신고가 1건 이상이고 유효한 좌표가 있는 전체 2,096곳**이다. `load_context()`의 기본 `max_spots=None`은 전체를 뜻한다. 300지점 중간판은 `routes/intermediate_300/`에 보존하였다.
- Context는 입력 파일 갱신 때 다시 만든다. 기본적으로 도로행렬을 지연 준비하므로 현황·접수 등급 조회만으로 경로 계산을 시작하지 않는다.
- 차도망은 OSMnx의 유성구 경계와 1,200m 버퍼이다. 방향성을 유지한 최단 주행 길이를 25km/h로 환산한다. 구청 주소를 지오코딩하고 최대 강연결 도로 성분에 좌표를 연결한다. 최종 최대 연결거리는 약 405m이고 이 연결 구간의 이동시간은 행렬에 더하지 않는다. 실시간 교통·신호대기는 포함하지 않는다.

## 경로·지표 정의

- 지점당 기본 점검시간은 5분이며 모든 조는 같은 근무 구간 안에 구청으로 복귀한다. 지점은 전체 조를 합쳐 한 번만 방문한다.
- 도착 시각이 속한 hour_block의 `score × risk_weight` 합을 최대화한다. OR-Tools의 시간 차원과 선택 방문 패널티를 사용한다. 여러 시간대에 걸치는 지점은 시간대별 복제 노드를 만들고 실제 지점당 활성 노드를 하나로 제한한다.
- 보상은 0.0001 단위 정수로 바꾸고, 같은 정수 보상에서는 이동시간을 줄인다. b3 해를 초기해로 넣고 GLS를 30초 제한으로 실행한다. 위험 가중 학습 목적함수가 b3보다 낮아지면 유효한 초기 incumbent를 유지한다. 248개 평가 날짜×조건에서 위험 가중 기대값 하한을 통과하였다. 전역 최적성은 보장하지 않는다.
- b1은 학습 빈도 상위 지점에서 서비스시간으로 가능한 최대 방문 수만큼 후보를 먼저 고르고 최근접 순서로 방문한다. b2는 학습 신고 합이 많은 동부터 순회하고 각 동 안에서 최근접 방문을 한다. 둘 다 같은 근무·서비스·복귀·지점 중복 제약을 적용한다.
- 기록상 포착 수는 **방문 지점과 도착 시간대가 같은 평가 신고 건수**이다. 5분 점검 순간의 실제 적발 수나 민원 감소량이 아니다. 근무시간당 포착 수의 분모는 `차량 수 × 근무 구간 시간`이다.
- 평가 날짜는 2024년 10~12월의 평일 62일이며 공휴일은 주말로 분류한다. 10~14시/17~21시 × 1명/2명의 네 조건을 날짜별로 짝지어 비교한다. 부트스트랩은 날짜 2,000회 재표본의 95% 백분위 구간이다.
- 대표일은 각 조건의 `우선순위 경로 - b1` 일별 포착 차이를 기준으로 중앙값·90백분위·최솟값에 가장 가까운 날이다. 동률은 날짜순으로 정한다. 그림은 7.16인치·200dpi PNG이며 파일명·축 이름·단위로 구분한다.

## 접수 지원 규칙

지점 등급은 학습 신고 수에만 따른다. 기본값은 10건 이상 ‘반복’, 20건 이상 ‘상습’이며 기준값을 바꿀 수 있다. 접수일의 재생 시점까지 신고만 사용해 금일 순번과 묶음 번호를 계산한다. 묶음 번호는 그날 처음 등장한 지점 순서대로 `YYYYMMDD-001` 형식이며 같은 지점은 같은 번호를 유지한다.

| 조건 | 조치 구분 |
|---|---|
| 경로에 포함되고 접수 시각이 도착 예정 전인 경우 | 금일 순회 포함 |
| 도착 뒤 재발을 포함해 그 밖의 반복·상습 지점인 경우 | 순회 경로 반영 검토 |
| 그 밖의 경우 | 일반 처리 |

‘시설 개선 검토’는 상습 지점이거나, 반복 지점이면서 `child_zone_300m=1`이면 ‘해당’, 그 밖에는 ‘비해당’이다. 이 열은 조치 구분과 별개이다. **보호구역 지정시설 300m 이내는 지정시설 좌표의 반경 대리지표이며 법적 구역 내부가 아니다.** 회신 내용은 지점 등급과 금일 순번을 반영한 고정 틀의 미발송 초안이며 순회 시각이나 단속 일정은 포함하지 않는다. 묶음 집계는 현장 확인·회신을 묶어 보는 수단이며 차량별 과태료 기록을 합치지 않는다.

공개 API와 CSV는 `접수 일시`, `금일 순번`, `묶음 번호`, `지점 등급`, `조치 구분`, `시설 개선 검토` 등 행정 열 이름을 공통으로 쓴다. `overview_filtered`의 기본 등급 기준은 조회 기간 신고 수이며 `grade_basis="train"`으로 운영 기준을 선택할 수 있다. 순회·접수 등급은 항상 1~9월 운영 기준이다. 반복·상습 지점 수는 서로 다른 등급에 속한 지점 수이며, 상위 100개 지점 비중은 선택 기간·동·등급 안의 신고 건수로 계산한다.

방법 참고: [OR-Tools 선택 방문 패널티](https://developers.google.com/optimization/routing/penalties), [시간 창과 시간 차원](https://developers.google.com/optimization/routing/vrptw).

추가 기준선 b3는 optimized와 같은 시간대 점수×위험 가중치로 b1과 같은 수의 후보를 고르고 최근접 순서로 순회한다. `evaluate_b3`는 기존 세 방식의 파일을 변경하지 않고 `evaluation_b3_paired.csv`, `evaluation_with_b3_daily.csv`, `plans_b3.json`을 별도로 쓴다.

## 기본 방식·시연 캐시

`planner_choice.json`은 1~7월(alpha=5) 점수로 만든 계획을 8~9월 평일 39일에서 검증하여 고정하였다. 네 조건 일평균 caught 합은 optimized 13.3333, b3 12.1282로 optimized가 선택되었다. 차이 0.05 미만이면 b3를 택하는 규칙을 실행 전에 저장하였다. 10~12월 결과를 다시 실행하거나 선택 기준으로 쓰지 않았다.

`generate_plan()`은 기본적으로 이 선택을 읽는다. 같은 요일 구분·근무 구간·차량 수·위험 가중·점수 방식·서비스시간·주행속도·입력/모델 버전은 날짜와 독립적으로 캐시한다. `plan_for_day_type()`도 사용할 수 있다. `precompute_plans --workers 4`로 평일/주말 × 4표준 구간 × 차량1~3 × 위험 적용/미적용의 48조합을 저장하였다. 캐시 재생 시험에서 탐색 함수를 금지한 채 48조합을 모두 읽었다. 날짜는 도착 예정 열에만 다시 표기한다.

현황 등급과 운영 등급이 다른 지점 중 연간 20건 이상·1~9월 10건 미만인 36곳은 `data/processed/emerging_spots.csv`에 저장하였다. 현황용 후발 신고 추이 자료이며 순회 후보나 운영 등급 결정에 사용하지 않는다.
